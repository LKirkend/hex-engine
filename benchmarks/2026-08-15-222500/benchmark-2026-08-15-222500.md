## 1. Executive Summary & Regression Resolution

During recent tactical improvements (such as Edge-2 template seeding and border containment checks), the engine experienced throughput degradation to **~137k - 170k nodes/second (n/s)**. 

### Root Cause Analysis of Previous Regression:
1. **Uncached Floating-Point Calculations**: On every static leaf evaluation and move ordering candidate, `(dr * dr + dc * dc).sqrt()` was computed 121 times.
2. **Dense Grid Loops inside Inner Tree Nodes**: The containment defense loop iterated $11 \times 3 = 33$ grid cells for every candidate move at every node.
3. **Full 121-Cell Occupancy Scans**: `evaluate_for_player` checked all 121 squares regardless of whether stones were present.
4. **2-Bridge Checking on Empty BFS Nodes**: In 0-1 BFS `shortest_path`, 2-bridge offsets were explored from empty corridor squares.

### Optimizations Implemented:
1. **Precomputed Compile-Time `CENTER_11` Table**: Replaced floating-point Euclidean distance math with instant $O(1)$ memory lookup.
2. **Bitboard Active Stone Scanning**: Used `trailing_zeros()` bit scanning (`red_bb.0` and `blue_bb.0`) to scan only placed stones (e.g. 10 loops instead of 121 loops).
3. **SIMD 128-Bit Border Masks**: Replaced 66-iteration cell loops with hardware `POPCNT` instructions on bitboard masks (`Bitboard128::col_mask`).
4. **Occupancy-Guarded 2-Bridge BFS**: Only friendly occupied stones initiate 2-bridge hops during 0-1 BFS.
5. **Tiered Move Ordering (`get_fast_promising_moves`)**: Full pattern matching is applied at root/shallow plies (`ply <= 1`), while deep tree nodes (`ply >= 2`) utilize zero-allocation SIMD neighbor expansion and center lookup.
6. **L1 Cache-Fitting BFS Queues**: Resized BFS distance and deque arrays from 784 bytes to 512 bytes, fitting within standard L1 cache lines.

## 4. Methodology & Environmental Parameters

- **Hardware:** Apple M-series Silicon, unified memory architecture.
- **Transposition Table:** 1,048,576 entries (64-byte aligned buckets with 64-bit Zobrist hashes).
- **Search Paradigm:** Principal Variation Search (PVS) with Late Move Reductions (LMR), alpha-beta pruning, iterative deepening, and sudden-death flood-fill shortcuts.
- **Reproducibility:** Run `./build/hex_benchmark` from the repository root after building release targets.

---

## 5. Recommendations for Further Scaling (Targeting 2M+ n/s)

1. **SIMD AVX2 / NEON Flood-Fill BFS**: Replace the array-based 0-1 BFS with bitboard parallel wave propagation (`step = (front.expand() & empty)` until destination edge is reached).
2. **Transposition Table Prefetching**: Issue CPU software prefetch instructions (`_mm_prefetch` / `core::arch::aarch64::prefetch`) on child Zobrist hashes before evaluating candidates.
3. **Lockless Shared TT for SMP Search**: Scale multi-threaded root search across physical cores using lazy SMP.
