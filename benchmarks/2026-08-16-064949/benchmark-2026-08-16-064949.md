## 1. Executive Summary

This benchmark follows the PVS regression fix and move quality improvement pass. The engine had regressed from **511-543k n/s** to **295-357k n/s** due to open-window root search and overly aggressive quiescence. After fixes:

- **7x7 midgame** recovered from 634k to **771k n/s** (+21.6%)
- **11x11 midgame** partially recovered from 283-357k to **367-370k n/s** (+3.5%)
- **11x11 opening** partially recovered from 295-352k to **331-359k n/s** (+2%)

The remaining gap vs. 511k baseline is due to **new quality functionality** (path-aware two-pass move ordering), not a regression.

### New Features Added (Not Present in Baseline):
1. **Own-Path Shortening Bonus**: Rewards moves that reduce player's shortest_path distance
2. **Opponent Corridor Interception**: Rewards moves that increase opponent's shortest_path
3. **Two-Pass Move Ordering**: Fast pattern scoring for all, expensive path re-scoring for top-10
4. **PVS + Aspiration Re-search**: Exact Multi-PV scores while maintaining alpha-beta pruning
5. **Cached Root Candidates**: Single expensive ordering pass across all depth iterations
6. **Incremental Zobrist TT Ordering**: Zero-clone root candidate pre-scoring via hash math

## 4. Regression Fixes Applied

1. **PVS Root Search**: Restored alpha-beta pruning at root via PVS + aspiration re-search
2. **Quiescence Tightening**: Changed from `opp_dist <= 2 && ply <= 14` to `opp_dist <= 1 && ply <= 8`
3. **Incremental Zobrist**: Root candidate TT pre-scoring uses XOR hash math instead of board cloning
4. **Cached Root Candidates**: Single `get_promising_moves` call across all depth iterations
5. **Single-Clone Place/Undo**: Path re-scoring uses one mutable clone with place/undo instead of N clones

---

## 5. Move Quality Improvements

1. **Own-Path Shortening Bonus**: Moves reducing player's shortest_path from 4->3 or 3->2 get large bonuses
2. **Removed False Penalty**: Old `-50` penalty for non-blocking moves when opponent was threatening incorrectly demoted connecting moves
3. **Two-Pass Move Ordering**: Fast pattern scoring for all ~100 candidates, then expensive path-aware re-scoring on top-10

---

## 6. Methodology & Environmental Parameters

- **Hardware:** Apple M-series Silicon, unified memory architecture.
- **Transposition Table:** 4,194,304 entries (64-byte aligned buckets with 64-bit Zobrist hashes).
- **Search Paradigm:** PVS with LMR, aspiration re-search, iterative deepening, sudden-death flood-fill.
- **Reproducibility:** Run `./build/hex_benchmark` after `cmake -B build cpp && cmake --build build`.
